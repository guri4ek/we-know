# C4: цільова архітектура MVP

Статус: **цільова MVP-модель**, 2026-10-11. Реалізовано Symfony kernel/Twig/GET skeleton і classification частину етапу 1: Jev adapter/DI, taxonomy/corpus, тести й evaluation CLI. Selector, application answer flow та persistence ще не реалізовані. Діаграми нижче описують цільову архітектуру; фактичний результат етапу 1 наведено у verification.

Діаграми використовують семантику C4 зі звичайною Mermaid-нотацією: тип елемента вказаний у кожному блоці, стрілки підписані. Межа системи — We Know, зовнішній сервіс — TypeSafe. C4 container тут означає виконуваний застосунок або сховище, а не обов'язково Docker. [Офіційна модель C4](https://c4model.com/diagrams) не вимагає всіх чотирьох рівнів; L4 варто додати після появи доменного коду, коли він пояснюватиме реальні складні взаємозв'язки.

## L1 — System Context

```mermaid
flowchart LR
    visitor["Відвідувач<br/>Person<br/>Ставить питання та ділиться відповіддю"]
    reader["Одержувач посилання<br/>Person<br/>Переглядає незмінний вердикт"]
    editor["Власник / редактор<br/>Person<br/>Готує каталог відповідей"]
    system["We Know / Instant Answer<br/>Software System<br/>Контекстуальні абсурдні відповіді та permalink"]
    jev["TypeSafe / Jev<br/>External Software System<br/>Класифікує intent і topic"]
    visitor -->|"Надсилає питання, отримує вердикт · HTTPS"| system
    reader -->|"Відкриває поширений URL · HTTPS"| system
    editor -->|"Імпортує перевірений контент · CLI"| system
    system -->|"Питання і дозволені категорії · HTTPS JSON"| jev
    jev -->|"Вибрані enum та службові оцінки"| system
```

TypeSafe не генерує фінальну фразу. Читання збереженого вердикту не залежить від TypeSafe. Каталогом керує власник через майбутній CLI import; web admin у MVP немає.

## L2 — Containers

```mermaid
flowchart LR
    visitor["Відвідувач / одержувач<br/>Person"]
    editor["Редактор<br/>Person"]

    subgraph system["We Know — software system boundary"]
        ui["Web UI у браузері<br/>Container · HTML / vanilla JS<br/>SSR-сторінки; fetch для форми, без SPA"]
        app["Symfony application<br/>Container · PHP 8.2+ / Symfony 7.4 / Twig<br/>HTTP та CLI; класифікація, вибір, persistence"]
        db[("Реляційна БД<br/>Container · SQLite dev / PostgreSQL prod<br/>Каталог, eligibility, знімки вердиктів")]
    end
    visitor -->|"Вводить питання / читає результат"| ui
    ui -->|"GET / та /a/id · HTTPS HTML"| app
    ui -->|"POST /answer · HTTPS JSON"| app
    app -->|"Серверний виклик класифікації · HTTPS JSON"| jev
    app -->|"Читання каталогу / запис і читання вердиктів · DBAL SQL"| db
    editor -->|"Імпорт каталогу · php bin/console"| app
```

Web UI доставляється тим самим Symfony-застосунком; окремого frontend deploy немає. База на діаграмі — одна логічна роль, а не одночасна реплікація SQLite і PostgreSQL. У dev це локальний файл, у production пропонується PostgreSQL connection. Public assets обслуговує web server; web server — deployment detail, не окрема бізнес-система.

## L3 — Components у Symfony application

```mermaid
flowchart TB
    browser["Web UI<br/>External to application container"]
    jev["TypeSafe / Jev<br/>External system"]
    db[("Relational DB<br/>External container")]
    subgraph app["Symfony application container"]
        http["AnswerController<br/>Component · Symfony Controller<br/>Input, origin, limits, HTTP contract"]
        pages["Page controllers + Twig<br/>Component · SSR<br/>Головна, About, permalink HTML"]
        usecase["AnswerQuestion<br/>Component · Application service<br/>Координує classify, select, persist"]
        classifier["JevClassifier<br/>Component · HttpClient adapter<br/>Реалізує QuestionClassifier; валідований enum / failure"]
        selector["ContextualAnswerSelector<br/>Component · PHP domain logic<br/>Fallback tiers, deduplication, random"]
        catalog["AnswerRepository<br/>Component · DBAL adapter<br/>Активні фрази та eligibility"]
        verdicts["VerdictRepository<br/>Component · DBAL adapter<br/>Незмінні знімки та lookup ID"]
        importer["ImportCatalogCommand<br/>Component · Console<br/>Валідація й атомарне оновлення контенту"]
    end
    browser -->|"POST JSON"| http
    browser -->|"GET HTML"| pages
    http -->|"Валідоване питання"| usecase
    usecase -->|"classify(question)"| classifier
    classifier -->|"Один choice-запит для intent/topic · HTTPS"| jev
    usecase -->|"Classification або fallback status"| selector
    selector -->|"Перший непорожній пул"| catalog
    usecase -->|"Зберегти snapshot; commit до HTTP 201"| verdicts
    pages -->|"Знайти готовий вердикт за ID"| verdicts
    importer -->|"Перевірений каталог"| catalog
    catalog -->|"SQL / параметризовані запити"| db
    verdicts -->|"SQL / коротка транзакція"| db
```

Selectors не знають transport/JSON Jev. Адаптер не знає бібліотеки жартів. HTTP-контролер не реалізує класифікацію чи random. Усі компоненти — частини одного процесу/кодового проєкту, не мережеві мікросервіси.

Каталог міститиме `humor_mechanism` у eligibility, заповнений під час підготовки контенту; selector його ігнорує. Для VerdictRepository запропоновано текстові snapshots, nullable eligibility FK і короткий `decision_context`: категорії класифікатора, фактично вибраний пул/механізм та причини fallback. Це ще не затверджений контракт збереження; [модель даних](data.md) розділяє прийняті вимоги й пропозицію.

## Dynamic — створення й повторне читання

```mermaid
sequenceDiagram
    actor User
    participant UI as Browser / vanilla JS
    participant HTTP as Symfony Controller
    participant App as AnswerQuestion
    participant Jev as Jev adapter / TypeSafe
    participant Select as Contextual selector
    participant DB as Relational DB
    User->>UI: Submit question
    UI->>HTTP: POST /answer JSON
    HTTP->>HTTP: Validate input, origin and rate limits
    HTTP->>App: Valid question
    App->>Jev: Classify intent and topic
    alt Valid response within total deadline
        Jev-->>App: Classification
    else Timeout / provider failure / invalid response
        Jev-->>App: Typed failure
        App->>App: Mark failure and force universal ANY / GENERAL pool
    end
    App->>Select: Select from permitted tiers or forced universal pool
    Select->>DB: Read eligible active answers
    DB-->>Select: Candidate pool
    Select-->>App: Selected text, eligibility and selection context
    App->>DB: Persist text snapshots and proposed decision context, commit
    DB-->>App: Durable public ID
    App-->>HTTP: Verdict
    HTTP-->>UI: 201 JSON + Location
    UI-->>User: Plain text result and share URL
    User->>HTTP: GET /a/publicId
    HTTP->>DB: Read snapshot
    DB-->>HTTP: Same question and answer
    HTTP-->>User: SSR HTML + Open Graph
```

Відхилені input/origin/rate limit завершують запит до App/Jev. Порожній universal pool або persistence failure завершуються 503 і не видають permalink; це альтернативні failure paths до показаного успішного збереження. Відкриття permalink працює під час відмови Jev, якщо доступна БД.

## Deployment — мінімальний орієнтир

```mermaid
flowchart LR
    browser["Browser"]
    subgraph host["Application host · region TBD"]
        web["TLS web server<br/>document root: public/"]
        php["PHP-FPM + OPcache<br/>Symfony prod / debug off"]
        web -->|"FastCGI"| php
    end
    database[("PostgreSQL<br/>private connection / backups")]
    provider["TypeSafe API"]
    browser -->|"HTTPS"| web
    php -->|"DBAL / PostgreSQL protocol"| database
    php -->|"HTTPS / bounded duration"| provider
```

Хостинг, версія PostgreSQL, мережеві межі й резервні копії потребують конкретизації перед deployment. Worker mode/FrankenPHP не є стартовою умовою; рішення приймати за вимірами. Публікацію зараз не виконано.
